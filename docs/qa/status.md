## 6. 운영 규약 — 앞으로 증거를 어디에 남기나

| 무엇을 했나 | 어디에 남기나 |
| --- | --- |
| 회차 QA (전 기능 순회) | 노션 QA DB 에 새 회차 페이지 |
| PR 리뷰에서 지적별 실측 | 해당 PR 리뷰 본문의 검증 섹션 |
| 에뮬레이터·실서버 실측 | `.codex/qa-evidence/emulator/<검증한 HEAD sha>.json` |
| 시안·명세에 없어 판단으로 정한 것 | `docs/qa/assumptions.md` |

**지금 이 규약의 구멍 두 개:**

1. **증거 대장이 `.gitignore` 라 로컬에만 있다.** 팀이 공유할 수도, 유실을 막을 수도 없다. 추적 대상으로 올리든지(`.gitignore` 예외), 결과를 이슈·PR 본문으로 옮기든지 정해야 한다.
2. **상시 QA 는 발견된 결함(이슈)만 남고, "무엇을 봤는데 멀쩡했나" 는 안 남는다.** 그래서 되짚으면 공백처럼 보인다. 회차 QA 문서의 "정상 확인" 절이 이걸 메우는 유일한 수단이다.

**원칙: "누가 했나" 는 기록하지 않는다.** 증거 대장은 도구·사람 무관 공용이고, 남아야 하는 것은 *어느 리비전에서 무엇이 검증됐나* 뿐이다.

## 7. 3차 QA 계획

**우선순위** — 5절의 구멍이 겹치는 순서.

1. **애프터노트** (잔여 14 · 머지 60건 · 증거 3건) — 최우선
2. **설정** (잔여 9 · 스크린샷 0 · 증거 1건 차단) — 화면 17개 전수 순회
3. **타임레터** (잔여 6 · 스크린샷 0장)
4. **마음의 기록·온보딩·수신자** — 회귀 확인 수준

**미확인으로 남아 있는 것** (2차 QA 에서 이월)

- 수신자 열람 승인 이후 화면 — 관리자 승인 수단이 없어 dev 환경에서 도달 불가
- 비즈니스·추억 노트 등록 완주 — 수신자 추가 진입점 문제가 선행
- 구독 화면 — 미구현("구독 후 기록하기" 는 팝업만 닫힘)

**실행 시 제약**

- dev 서버(afternote.kro.kr)는 **03~12시(KST) 닫힌다.** 그 시간대 실패는 코드보다 시간대를 먼저 의심할 것.
- develop 기준 debug 빌드로 진행하고, 검증한 HEAD sha 를 문서 상단에 적는다.
- **결함뿐 아니라 "정상 확인" 항목도 적는다.** 그게 다음 회차에서 공백을 없애는 유일한 방법이다.
